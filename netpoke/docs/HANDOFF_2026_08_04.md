## 1. What this project is

MPhil Computer Science thesis (KNUST) by **Afram Visca Gyebi**. The base paper
is **SlowPoke** (Xie et al., NSDI 2026), which predicts the optimal throughput
of a microservice application by pausing non-target services with
`SIGSTOP`/`SIGCONT` (via a controller called POKER) and measuring the resulting
slowdown. The thesis claim:

> SlowPoke's predictions degrade for I/O-bound microservices because `SIGSTOP`
> does not stop network I/O — the service keeps receiving data during the pause,
> corrupting the measurement. **NetPoke** fixes this by adding a Linux `sch_plug`
> egress hold synchronised with each `SIGSTOP`/`SIGCONT` pair inside POKER.

Repo: `https://github.com/gvafram3/netpoke`, branch `netpoke/experiments`.
Local Windows copy: `g:\projects\netpoke`. GitHub username: `gvafram3`.

## 3. What has been built on top of SlowPoke

Three files modified in `slowpoke/src/poker/`:

- `poker.c` — unconditional `poker: pause_start` / `poker: pause_end` log
  markers on every `SIGSTOP`/`SIGCONT` pair, independent of NetPoke flag.
  Required so the residual-I/O sampler can correlate samples against pause
  windows in the SIGSTOP-only condition.
- `net_hold.c` — `net_hold()` / `net_release()` via Linux `sch_plug`. Holds
  egress before `SIGSTOP`, releases after `SIGCONT`. Persistent `AF_NETLINK`
  socket with `SO_RCVTIMEO` (100ms). Falls back to `system("tc ...")` if
  netlink fails. Controlled by `SLOWPOKE_NETPOKE=1` env var.
- `net_hold.h` — header.

Docker images already built and pushed to Docker Hub as
`gvafram3/mucache:<bench>-pokerpp-netpoke` for all four apps. No rebuild
needed unless `poker.c` or `net_hold.c` change.

Two yaml directories per app (generated by `patch_all_netpoke_yamls.sh`):
- `<bench>/yamls/netpoke/` — `gvafram3` image, `NET_ADMIN`, `SLOWPOKE_NETPOKE=1`
- `<bench>/yamls/netpoke-sigstop/` — same image, `NET_ADMIN`, `SLOWPOKE_NETPOKE=0`

Both are required. Without `netpoke-sigstop/`, `run.sh` silently falls back to
the plain `yizhengx` images which lack pause markers.

## 4. Results so far (all single-run — need 3+ repetitions for mean/spread)

### Table B1 — Phase 1 baseline RMSE (SIGSTOP-only, L0)

| App | Throughput | RMSE |
|---|---|---|
| Boutique | 1937.3 req/s | 2.57% |
| Hotel | 723.9 req/s | 20.65% |
| Social | 959.9 req/s | 14.01% |
| Movie | 550.8 req/s | 12.21% |

Boutique's 2.57% closely matches the paper's ~2.07%. Hotel is volatile (was
10.23% in an earlier run with nothing else changed).

### Table I1 — Phase 3 I/O-gap RMSE (SIGSTOP-only, L2 injection)

| App | L0 RMSE | L2 RMSE | Δ |
|---|---|---|---|
| Social | 14.01% | 33.61% | +19.60pp — headline RQ1 result |
| Movie | 12.21% | 13.84% | +1.63pp |
| Boutique | 2.57% | 3.53% | +0.96pp |
| Hotel | 20.65% | 17.51% | −3.14pp — reversed (volatility, not hypothesis failure) |

### Table N1 — Residual I/O during pause windows (in-pod sampler)

| App | Level | SIGSTOP-only | NetPoke-on | Change |
|---|---|---|---|---|
| Boutique | L0 | 8.43% | 7.06% | flat |
| Boutique | L2 | 3.28% | 4.28% | flat |
| Hotel | L2 | 9.52% | 3.33% | ~2.9x reduction |
| Social | L2 | 8.91% | 4.00% | ~2.2x reduction |
| Movie | L2 | 6.89% | 1.59% | ~4.3x reduction |

### Table N2 — RMSE restoration (⚠️ collected before injection-yaml bug fix — needs re-run)

| App | L0 | SIGSTOP-only L2 | NetPoke-on L2 | Change |
|---|---|---|---|---|
| Boutique | 2.57% | 3.53% | 10.26% | +6.73pp worse |
| Hotel | 20.65% | 17.51% | 10.25% | −7.26pp better |
| Social | 14.01% | 33.61% | 18.69% | −14.92pp, **76% recovery** |
| Movie | 12.21% | 13.84% | 10.23% | −3.61pp better |

| App | SIGSTOP-only L0 | NetPoke-on L0 | Change |
|---|---|---|---|

| Movie | 12.21% | 12.13% | flat |

### Boutique fan-out finding (source read, no cluster time)

Boutique's `cart` handler uses an in-process `sync.Map`. The Redis/Dapr calls
exist in `cart.go` but are commented-out dead code. Hotel, social, and movie
all make real synchronous I/O calls on their causal target's request path.
This explains boutique's flat I/O-gap signal, flat residual-I/O, and RMSE
regression under NetPoke. Full writeup:
`netpoke/results/cluster/netpoke/tables/BOUTIQUE_FANOUT_FINDING.md`.

## 5. Bugs found and fixed

1. **`net_hold.c` netlink silent hang** — `recvmsg()` had no timeout, freezing
   POKER's pause thread permanently on the first toggle. Fixed with
   `SO_RCVTIMEO` (100ms). Confirmed: 362/362 pause events used netlink, avg
   0.48ms.

2. **`apply_io_injection.sh` patching the wrong yaml directory** — always
   patched `<bench>/yamls/*.yaml` (plain), but `run.sh` deploys from
   `netpoke/` or `netpoke-sigstop/` when `SLOWPOKE_NETPOKE=1` or
   `SLOWPOKE_YAML_SUBDIR` is set. Any NetPoke-tagged L1/L2 run deployed from
   a yaml that never received the netem delay. Fixed: script now mirrors
   `run.sh`'s directory-selection logic. **This bug affects Table N1's L2 rows
   and all of Table N2 — they need re-measuring.**

3. **`patch_all_netpoke_yamls.sh` only generated `netpoke/`** — `netpoke-sigstop/`
   was never created, so runs 1 and 3 silently fell back to plain `yizhengx`
   images. Fixed: script now generates both directories in one pass.

4. **`EXPERIMENT_RUNBOOK.md` heredoc bug** — run 3 used `<<'EOF'` (prevents
   `$RESULTS_DIR` expansion). Fixed to `<<EOF`. Added `|| exit 1` to
   `run_io_medium.sh` call.

All four fixes committed and pushed as commit `d2ef98c` on
`origin/netpoke/experiments`, pulled to the GCP VM.

**What has NOT been done yet (AWS is not running):**
- `initialize-aws.sh` has not been created or verified. The GCP equivalent is
  `02_initialize_cluster.sh` — the AWS version needs to install Docker,
  Kubernetes 1.29, and Istio 1.18 on all nodes via SSH, then run `kubeadm
  init` on the control node and `kubeadm join` on each worker.
- The cluster has not been created (`setup_ec2_cluster.py` not yet run).
- No experiments have been run on AWS.

**The `ec2_cluster.py` script as-is:**
- Creates 2 × `m5.2xlarge` (control) and N × `m5.large` (workers) by default.
  The `setup_ec2()` function hardcodes `m5.2xlarge` for the first two instances
  and `m5.large` for workers. For a 12-worker setup: `-n 12`.
- Saves instance IDs to `~/cluster_info/instances`, IPs to
  `~/cluster_info/ec2_ips`. Control node IP is `head -1 ~/cluster_info/ec2_ips`.
- SSH key written to `~/cluster_info/slowpoke-expr.pem`.
- Security group opens all traffic from `0.0.0.0/0` (fine for a short-lived
  experiment cluster, not for production).
- The script calls `get_vpc()` at module import time — it will fail immediately
  if `aws` CLI is not configured. Run `aws sts get-caller-identity` first.
